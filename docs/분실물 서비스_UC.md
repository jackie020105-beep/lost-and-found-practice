## UC_01 — 분실물 보관 여부·위치 조회

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_01 / 분실물 보관 여부·위치 조회 |
| 상태 / 우선순위 | 확정 / 높음 |
| 사용자와 목표 | **분실 학생**이 분실물을 조회하여 보관 여부와 공개 허용 범위의 보관 위치를 확인함으로써, 행정실 방문과 반복 문의를 줄인다. |
| 관련 고객 요구·정책 ID | NEEDS_1, NEEDS_6, SC1 / Pol_00, Pol_01, Pol_02 |
| 관련 SRS ID | FR_00, FR_01, FR_07, NFR_00, NFR_01, NFR_02 |
| 사전조건 / 시작 사건 | **사전조건:** 서비스에 조회 가능한 물품 정보가 존재할 수 있다. <br> **시작 사건:** 분실 학생이 방문 전에 분실물 조회를 선택한다. |
| 기본 흐름 | 1. 학생이 분실물 조회를 선택한다. <br> 2. 시스템이 검색 조건 입력 방법을 제공한다. <br> 3. 학생이 검색 조건을 입력하고 조회를 요청한다. <br> 4. 시스템이 등록된 물품 중 조건에 맞는 정보를 검색한다. <br> 5. 시스템이 공개가 허용된 보관 여부와 보관 위치를 표시한다. <br> 6. 학생이 결과를 확인한다. |
| 대안·예외 흐름 | **A1 — 검색 결과 없음:** 4단계 → 일치 물품이 없음 → 시스템이 검색 결과 없음을 알리고 문의 방법 확인을 제시 → 학생은 검색 조건을 바꾸어 2단계로 복귀하거나 UC_02로 이동한다. <br><br> **A2 — 공개 제한 정보:** 5단계 → 결과에 공개 제한 항목이 포함됨 → 시스템이 제한 항목을 표시하지 않고 허용된 정보만 표시 → 6단계로 복귀한다. <br><br> **[논의] A3 — 검색 조건 불충분 또는 모호:** 4단계 → 다수의 유사 물품이 검색됨 → 결과를 어떤 기준으로 정렬·필터링하고 재검색을 어떻게 유도할지 미정 → 정책 확정 전까지 종료 또는 2단계 복귀 방식을 결정해야 한다. |
| 사후조건 | **성공:** 학생이 공개 허용 범위 내에서 물품의 보관 여부와 위치를 확인한다. <br> **실패·취소:** 물품 데이터나 개인 정보는 변경되지 않으며, 조회 결과가 없거나 학생이 조회를 취소한 사실의 보존 여부는 미정이다. |
| 미확정 사항·고객 질문 | Q_01 검색 조건(물품명·습득일·분류 등)은 무엇인가? <br> Q_02 결과에 보관 여부·위치 외 어떤 정보를 공개할 수 있는가? <br> Q_03 보관 위치를 담당 부서명, 건물, 창구 중 어느 수준까지 공개할 것인가? |

|---|---|

| 상태 / 우선순위 | 확정 / 높음 |
| 사용자와 목표 | **분실 학생**이 보관 담당 부서와 문의 방법을 확인하여, 필요한 경우 올바른 창구로 문의한다. |

| 기본 흐름 | 1. 학생이 문의 방법 확인을 선택한다. <br> 2. 시스템이 보관 담당 부서와 문의 방법을 표시한다. <br> 3. 학생이 안내를 확인한다. |
| 대안·예외 흐름 | **A1 — 문의 정보 미등록:** 2단계 → 담당 부서 또는 문의 방법이 등록되지 않음 → 시스템이 안내를 제공할 수 없음을 표시 → Use Case를 종료한다. <br><br> **[논의] A2 — 개인 연락처 포함 요청:** 2단계 → 표시 후보에 개인 휴대전화 번호가 포함됨 → 개인 번호는 표시하지 않고 대표 문의 채널로 대체해야 함 → 대표 채널이 없을 때의 안내 문구와 종료 방식은 확정이 필요하다. |
| 사후조건 | **성공:** 학생이 개인 연락처 없이 담당 부서의 문의 방법을 확인한다. <br> **실패·취소:** 문의 정보가 없거나 학생이 취소해도 물품 정보와 개인정보는 변경되지 않는다. |
| 미확정 사항·고객 질문 | Q_04 부서명, 운영 시간, 대표 전화, 이메일 등 어떤 항목을 표시할 것인가? <br> 대표 문의 채널이 없을 경우 대체 안내는 무엇인가? **[논의]** |

## UC_03 — 습득물 앱 등록

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_03 / 습득물 앱 등록 |
| 상태 / 우선순위 | 확정 / 높음 |
| 사용자와 목표 | **습득 학생**이 자신이 습득한 물품을 앱에서 바로 등록하여, 물품이 분실물 관리 절차에 반영되도록 한다. |
| 관련 고객 요구·정책 ID | S3, DEC_00(추가 확정 사항), C_1 / Pol_02, Pol_03 |
| 관련 SRS ID | FR_02, NFR_01, NFR_04 |
| 사전조건 / 시작 사건 | **사전조건:** 습득 학생이 서비스를 이용할 수 있다. 실제 학교 인증 연동은 사용하지 않는다. <br> **시작 사건:** 습득 학생이 습득물 등록을 선택한다. |
| 기본 흐름 | 1. 학생이 습득물 등록을 선택한다. <br> 2. 시스템이 등록 입력 항목을 제공한다. <br> 3. 학생이 습득 물품 정보를 입력하고 등록을 요청한다. <br> 4. 시스템이 입력값을 검증한다. <br> 5. 시스템이 습득물 등록 정보를 저장하고 등록 완료를 알린다. |
| 대안·예외 흐름 | **A1 — 필수 입력 누락 또는 형식 오류:** 4단계 → 입력값이 규칙을 충족하지 않음 → 시스템이 오류 항목을 알리고 수정 입력을 요청 → 3단계로 복귀한다. <br><br> **[논의] A2 — 기존 등록 물품과 중복 가능:** 4단계 → 동일·유사 물품의 기존 등록 여부를 확인할 기준이 미정 → 중복 경고, 등록 허용, 관리자 검토 중 어떤 대응을 할지 확정해야 한다. <br><br> **[논의] A3 — 등록 후 인계 안내:** 5단계 → 등록은 완료됐지만 물품 인계 장소·방법의 안내 범위가 미정 → UC_06 포함 여부 및 안내 정책을 확정해야 한다. |
| 사후조건 | **성공:** 습득 학생이 입력한 물품 등록 정보가 저장되고, 후속 관리 대상으로 사용할 수 있다. <br> **실패·취소:** 유효하지 않은 입력은 저장하지 않는다. 취소 시 임시 입력값의 보존 여부는 미정이다. |
| 미확정 사항·고객 질문 | Q_05 앱 등록의 필수 입력 항목과 등록 직후 제공할 안내는 무엇인가? <br> Q_07 앱 등록 정보와 센터 접수 물품이 동일한 경우 어떻게 확인·처리할 것인가? <br> 인증 없이 등록을 식별·관리할 방법은 무엇인가? **[논의]** |

## UC_04 — 센터 접수 물품 등록

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_04 / 센터 접수 물품 등록 |
| 상태 / 우선순위 | 확정 / 높음 |
| 사용자와 목표 | **행정 담당자**가 분실물 센터로 접수된 습득 물품을 등록하여, 학생이 조회하고 센터가 물품을 관리할 수 있는 기준 정보를 만든다. |
| 관련 고객 요구·정책 ID | NEEDS_2, NEEDS_7, SC2, DEC_01(추가 확정 사항), C_1 / Pol_02, Pol_03 |
| 관련 SRS ID | FR_03, NFR_01, NFR_03, NFR_04 |
| 사전조건 / 시작 사건 | **사전조건:** 습득 물품이 분실물 센터에 접수되어 있으며, 담당자가 등록 업무를 수행할 수 있다. <br> **시작 사건:** 행정 담당자가 센터 접수 물품 등록을 선택한다. |
| 기본 흐름 | 1. 담당자가 센터 접수 물품 등록을 선택한다. <br> 2. 시스템이 등록 입력 항목을 제공한다. <br> 3. 담당자가 접수 물품 정보를 입력하고 등록을 요청한다. <br> 4. 시스템이 입력값을 검증한다. <br> 5. 시스템이 물품 정보를 저장하고 관리 대상 물품으로 등록한다. |
| 대안·예외 흐름 | **A1 — 필수 입력 누락 또는 형식 오류:** 4단계 → 입력값이 규칙을 충족하지 않음 → 시스템이 오류 항목을 알리고 수정 입력을 요청 → 3단계로 복귀한다. <br><br> **[논의] A2 — 습득 학생 앱 등록 정보와 일치 가능:** 4단계 → 동일 물품으로 보이는 앱 등록 정보가 있음 → 담당자에게 후보 정보를 보여줄지, 중복 등록을 허용할지, 병합할지 미정 → 정책 확정 전까지 처리 방식을 결정해야 한다. <br><br> **[논의] A3 — 등록 권한 없음:** 1단계 또는 5단계 → 담당자의 권한을 판별해야 하나 학교 인증 연동은 제외됨 → 권한 확인 방식과 거부 시 안내를 정해야 하며, 해결되지 않으면 Use Case를 종료한다. |
| 사후조건 | **성공:** 센터 접수 물품 정보가 관리 대상 물품으로 저장된다. <br> **실패·취소:** 저장 전 오류 또는 취소가 발생하면 관리 대상 물품은 생성되지 않는다. 임시 입력값 보존 여부는 미정이다. |
| 미확정 사항·고객 질문 | Q_06 센터 접수 물품 등록의 필수 입력 항목과 등록 권한은 무엇인가? <br> Q_07 앱 등록 정보와 센터 접수 물품의 중복·연계 처리는 어떻게 하는가? <br> Q_10 등록 업무 부담의 기준선·측정 방식·개선 목표는 무엇인가? |

## UC_05 — 물품 보관·인도 상태 관리

| 항목 | 내용 |
|---|---|
| ID / 이름 | UC_05 / 물품 보관·인도 상태 관리 |
| 상태 / 우선순위 | 확정 / 높음 |
| 사용자와 목표 | **행정 담당자**가 관리 대상 물품의 상태를 기록·변경하여, 보관 중인 물품과 인도 완료 물품을 명확히 구분하고 정확한 조회 정보를 제공한다. |
| 관련 고객 요구·정책 ID | NEEDS_3, SC3, C_1 / Pol_02, Pol_03 |
| 관련 SRS ID | FR_04, FR_05, NFR_01, NFR_04 |
| 사전조건 / 시작 사건 | **사전조건:** 관리 대상 물품이 등록되어 있다. <br> **시작 사건:** 행정 담당자가 물품의 상태를 확인하거나 인도 처리 후 상태 변경을 선택한다. |
| 기본 흐름 | 1. 담당자가 관리 대상 물품을 선택한다. <br> 2. 시스템이 현재 상태를 표시한다. <br> 3. 담당자가 물품 상태를 `보관 중` 또는 `인도 완료`로 기록·변경한다. <br> 4. 시스템이 변경값을 검증한다. <br> 5. 시스템이 상태를 저장하고 변경 결과를 표시한다. |
| 대안·예외 흐름 | **A1 — 대상 물품 없음:** 1단계 → 선택한 물품이 존재하지 않거나 조회할 수 없음 → 시스템이 대상 물품을 찾을 수 없음을 알림 → 1단계로 복귀하거나 Use Case를 종료한다. <br><br> **[논의] A2 — 인도 완료 상태의 정정 요청:** 4단계 → 이미 `인도 완료`인 물품을 `보관 중`으로 변경하려 함 → 정정 가능 여부, 승인자 및 이력 보존 규칙이 미정 → 권한·절차가 확정되지 않으면 변경을 저장하지 않고 종료한다. <br><br> **[논의] A3 — 권한 없는 상태 변경:** 3단계 → 담당자별 변경 권한을 판별해야 하나 방식이 미정 → 변경 거부 및 안내 방식을 결정해야 한다. |
| 사후조건 | **성공:** 선택 물품의 상태가 `보관 중` 또는 `인도 완료`로 저장되고 조회 결과에 반영된다. <br> **실패·취소:** 기존 상태는 유지된다. 상태 변경 이력의 보존 여부와 정정 이력의 공개 범위는 미정이다. |
| 미확정 사항·고객 질문 | Q_08 상태 변경·정정 권한과 절차는 무엇인가? <br> `인도 완료` 처리의 판단 기준과 증빙 필요 여부는 무엇인가? **[논의]** <br> 상태 변경 이력을 저장할 것인가? 저장한다면 보존 기간은 얼마인가? **[논의]** |

## UC_06 — 습득물 맡김 장소 확인

| 항목 | 내용 |
