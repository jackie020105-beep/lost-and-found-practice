# 소프트웨어 요구사항 명세서(SRS) v0.1

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 |
| 문서 목적 | 교내 분실물 관리 서비스의 고객 요구사항을 기능 요구사항, 비기능 요구사항 및 정책으로 구조화한다. |
| 근거 문서 | `고객 요구사항.md` |
| 범위 | 분실물 조회, 습득 학생의 앱 등록, 분실물 센터 접수 물품 등록, 보관·인도 상태 관리, 담당 부서 문의 방법 안내 |
| 작성 기준 | 고객 요구사항에서 확정된 범위만 구현 요구사항으로 기술하고, 미정 사항은 별도 확인 사항으로 표시한다. |

## 1. 기능 요구사항

| ID | 기능 요구사항 | 근거 | 우선순위 | 확인 사항 |
|---|---|---|---|---|
| FR_00 | 시스템은 분실 학생이 방문 전에 분실물의 보관 여부를 조회할 수 있도록 해야 한다. | NEEDS_1, SC1 | 높음 | 검색 조건은 미정이다. |
| FR_01 | 시스템은 조회 결과에서 보관 중인 분실물의 보관 위치를 표시해야 한다. | NEEDS_1, SC1 | 높음 | 공개할 세부 위치 정보의 범위는 미정이다. |
| FR_02 | 시스템은 습득 학생이 습득한 물품을 앱에서 즉시 등록할 수 있도록 해야 한다. | 확정 사항: 습득물 등록 | 높음 | 등록 시점 및 필수 입력 항목은 확정됐으나, 세부 입력 항목은 추가 확인이 필요하다. |
| FR_03 | 시스템은 행정 담당자가 분실물 센터로 접수된 습득 물품을 관리하기 위해 물품 정보를 등록할 수 있도록 해야 한다. | NEEDS_2, SC2, 확정 사항: 습득물 등록 | 높음 | 필수 입력 항목과 역할별 등록 권한은 미정이다. |
| FR_04 | 시스템은 행정 담당자가 물품의 보관 상태를 기록하고 관리할 수 있도록 해야 한다. | NEEDS_3, SC3 | 높음 | 상태 변경 처리 권한은 미정이다. |
| FR_05 | 시스템은 각 물품을 최소한 `보관 중`과 `인도 완료` 상태로 구분하여 표시해야 한다. | NEEDS_3, SC3 | 높음 | 상태 정정 절차와 조건은 미정이다. |
| FR_06 | 시스템은 분실 학생이 보관 담당 부서와 문의 방법을 확인할 수 있도록 안내를 제공해야 한다. | NEEDS_4, SC6 | 높음 | 담당 부서명, 운영 시간, 문의 채널 등 표시 항목은 미정이다. |
| FR_07 | 시스템은 조회 화면에서 정책상 공개가 허용된 물품 정보만 표시해야 한다. | NEEDS_6, S4 | 높음 | 공개 가능 항목의 상세 목록은 정보보호 담당자 확인이 필요하다. |

## 2. 비기능 요구사항(품질 요구사항)

| ID | 품질 특성 | 비기능 요구사항 | 근거 | 수용 기준 또는 확인 사항 |
|---|---|---|---|---|
| NFR_00 | 개인정보 보호 | 시스템은 조회 화면에 개인 휴대전화 번호를 표시해서는 안 된다. | NEEDS_6, SC8 | 개인 휴대전화 번호가 조회 결과 및 문의 안내에 노출되지 않는다. |
| NFR_01 | 데이터 보호 | 시스템은 실제 개인정보를 저장·처리·표시하지 않고 가상 데이터만 사용해야 한다. | C_1 | 테스트·시연 데이터에 실제 개인정보를 포함하지 않는다. |
| NFR_02 | 사용성 | 분실 학생은 행정실 방문 전에 보관 여부, 보관 위치 및 문의 방법을 한 서비스에서 확인할 수 있어야 한다. | NEEDS_1, NEEDS_4 | 화면 구성과 사용성 측정 기준은 추후 확정한다. |
| NFR_03 | 업무 효율성 | 시스템은 행정 담당자의 분실물 센터 접수 물품 등록 업무 부담을 줄일 수 있도록 등록 절차를 지원해야 한다. | NEEDS_7, 확정 사항: 습득물 등록 | 현 소요 시간, 측정 방법 및 개선 목표 수치는 미정이므로 v0.1에서는 정량 수용 기준을 두지 않는다. |
| NFR_04 | 운영 적합성 | 시스템은 실제 학교 인증 연동 없이 동작해야 한다. | C_1 | 학교 계정 인증, SSO 등 외부 인증 연동을 구현 범위에 포함하지 않는다. |

## 3. 정책 및 범위 제약

| ID | 정책 | 근거 | 적용 및 비고 |
|---|---|---|---|
| Pol_00 | 조회 목적에 필요한 정보만 공개한다. | NEEDS_6, S4 | 공개 정보의 항목과 상세 수준은 정보보호 담당자의 검토 후 확정한다. |
| Pol_01 | 개인 휴대전화 번호는 공개하지 않는다. | NEEDS_6, SC8 | 담당 부서의 문의 방법 안내와 개인 연락처 공개를 명확히 구분한다. |
| Pol_02 | 개발·시연에는 가상 데이터만 사용한다. | C_1 | 실제 개인정보 및 실제 학교 구성원 정보의 사용을 금지한다. |
| Pol_03 | 실제 학교 인증 연동은 이번 개발 범위에서 제외한다. | C_1 | 인증 연동이 필요해질 경우 별도 요구사항과 보안 검토를 수행한다. |
| Pol_04 | 사진 업로드를 이용한 유사 분실물 조회 기능은 이번 개발 범위에서 제외한다. | SC5 | 후속 개선 후보로 관리한다. |
| Pol_05 | 사진 매칭 결과의 자동 알림 기능은 이번 개발 범위에서 제외한다. | SC7 | 수신 정보 등록 및 발송 기능을 이번 버전에 포함하지 않는다. |
| Pol_06 | 습득물을 맡길 장소 안내 기능의 포함 여부는 확정 전까지 보류한다. | NEEDS_5, SC4 | 기존 안내의 존재 여부와 프로그램 내 안내 필요성을 확인한 뒤 결정한다. |
