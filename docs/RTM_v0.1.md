# 요구사항 추적표(RTM) v0.1

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 |
| 목적 | 고객 요구사항과 SRS v0.1의 기능·비기능·정책 항목 간 추적성을 관리한다. |
| 원본 | `고객 요구사항.md` |
| 대상 명세 | `SRS_v0.1.md` |
| 추적 원칙 | 원문에서 확정된 요구사항만 연결한다. 미정 또는 제외된 항목은 상태와 결정 필요 사항을 함께 기록한다. |

| ID | 고객 요구사항 ID | 고객 요구사항 요약 | 연결된 SRS 항목 | 추적 상태 | 검증 기준 또는 후속 조치 |
|---|---|---|---|---|---|
| 01 | NEEDS_1 | 분실 학생이 방문 전에 물품의 보관 여부와 위치를 확인한다. | FR_00, FR_01, NFR_02 | 추적됨 | 보관 여부와 공개 허용 범위의 위치가 조회 화면에서 확인되어야 한다. 검색 조건 및 위치 공개 범위는 확정이 필요하다. |
| 02 | NEEDS_2 | 행정 담당자가 필요한 물품 정보를 등록한다. | FR_03 | 추적됨 | 행정 담당자가 분실물 센터 접수 물품 정보를 등록할 수 있어야 한다. 필수 입력 항목과 등록 권한은 확정이 필요하다. |
| 03 | NEEDS_3 | 행정 담당자가 보관 중 및 인도 완료 물품의 상태를 기록하고 구분한다. | FR_04, FR_05 | 추적됨 | 물품별 상태 기록과 `보관 중`·`인도 완료` 구분 표시가 가능해야 한다. 상태 변경·정정 권한은 확정이 필요하다. |
| 04 | NEEDS_4 | 분실 학생이 보관 담당 부서와 문의 방법을 확인한다. | FR_06, NFR_02 | 추적됨 | 조회 화면 또는 안내 화면에서 담당 부서와 문의 방법을 확인할 수 있어야 한다. 표시 항목은 확정이 필요하다. |
| 05 | NEEDS_5 | 습득 학생이 습득물을 맡길 장소를 안다. | Pol_06 | 보류 | 프로그램 내 안내 기능 포함 여부를 결정한다. 포함 결정 시 별도 기능 요구사항을 추가하고 추적표를 갱신한다. |
| 06 | NEEDS_6 | 조회 목적에 필요한 정보만 공개하고 개인 휴대전화 번호는 공개하지 않는다. | FR_07, NFR_00, NFR_01, Pol_00, Pol_01, Pol_02 | 추적됨 | 공개 허용 정보만 표시하고 개인 휴대전화 번호는 표시되지 않아야 한다. 공개 항목 목록은 정보보호 담당자가 확정한다. |
| 07 | NEEDS_7 | 행정 담당자의 물품 등록 부담을 줄인다. | NFR_03 | 부분 추적 | 등록 절차가 업무 부담 완화를 지원해야 한다. 기준선, 측정 방식 및 정량 목표가 미정이므로 수용 기준을 확정해야 한다. |
| 08 | C_1 | 가상 데이터를 사용하며 실제 개인정보 및 학교 인증 연동을 제외한다. | NFR_01, NFR_04, Pol_02, Pol_03 | 추적됨 | 테스트·시연 데이터에 실제 개인정보가 없어야 하며, 학교 계정 인증 또는 SSO 연동이 없어야 한다. |
| 09 | 확정 사항: 습득물 등록 | 습득 학생은 습득 물품을 앱에서 바로 등록하고, 행정 담당자는 분실물 센터 접수 물품을 관리하기 위해 등록한다. | FR_02, FR_03, NFR_03 | 추적됨 | 습득 학생의 앱 등록과 행정 담당자의 센터 접수 물품 등록이 각각 가능해야 한다. |
